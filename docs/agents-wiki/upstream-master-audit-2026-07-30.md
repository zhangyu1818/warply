## Ported Or Adapted

- `222903cb4` Ported the markdown HTML comment stripping fix. `<!-- ... -->` rendered as visible text because the shared `markdown_parser` had no comment handling at either the block or inline level. Added `parse_html_comment` and `parse_html_comment_block` to consume comments at both levels, with `code_span` ordered ahead of the inline comment branch so `` `<!-- x -->` `` stays literal and an unterminated `<!--` fails (left literal per CommonMark). Inline comments become `InlineToken::Comment`, discarded without emitting a fragment. Cherry-picked cleanly (auto-merge); the 6 regression tests applied to the fork's singular `markdown_parser_test.rs`.
- `161dd1e51` Ported the worktree path quoting fix. `git worktree add` / `cd` commands generated by the New Worktree tab-config flow interpolated the filesystem path without quoting, so paths containing a space were word-split and the commands failed. Double-quoted the path argument at all three generation surfaces (`session_config.rs`, `tab_config.rs`, `default_worktree.toml`). Branch names stay unquoted since git refs cannot contain spaces. Cherry-picked cleanly (auto-merge handled the fork's singular test filenames).
- `c0ad83627` Ported the vim indent/dedent operators. Added `VimOperator::Indent`/`Dedent` to the shared `crates/vim` parser, recognizing `<`/`>` as normal-mode and visual-mode operators with doubled-line forms (`>>`/`<<`), operator+motion, text objects, counts, and dot-repeat. The code editor routes them to `CodeEditorModel::indent`; the terminal command input treats them as a true no-op. Extracted `includes_trailing_newline()` so linewise selection excludes the trailing newline for indent/dedent (matching the existing `gc`/ToggleComment shape). Cherry-picked cleanly; the fork's vim crate lacked the `indent_operators_enabled` gate described in the upstream PR body (the actual diff did not include it), so the no-op terminal behavior is achieved via the `Indent | Dedent => {}` match arms.
- `7607743d5` Adapted the code-block file-references-respect-editor fix. `CodeSource::Link` now routes through `OpenDetectedFilePath` so the configured file editor resolves the path with line/column preserved; non-link sources keep `OpenCodeInWarp`. The code-block header button is labeled `Open file`; the terminal tooltip fallback keeps `Open in Warp`. Adapted: the regression test in `block_tests.rs` was rewritten to use `CodeSource::ProjectRules` (the removed `CodeSource::Skill` variant and `SkillReference` import are absent in this fork) and the upstream's orchestration-related test imports/functions were dropped.
- `e17deea4f` Adapted the macOS notarization polling resiliency fix. The bundler now submits each artifact once, retains the submission ID, and polls with bounded exponential backoff so a transient `notarytool info` transport failure no longer fails the release or creates duplicate submissions. Apple rejection still fails immediately and prints the log. Adapted: the fork uses API key auth (`--key`/`--key-id`/`--issuer`) instead of upstream's Apple ID/password/team-id, and the old post-command `$?` guard was folded into the `notarize_artifact` return code.
